# Бутики · учёт

Простая программа учёта закупок товаров у бутиков, депозитов и платежей. Три уровня, три экрана:

**Компании → Бутики → Закупка и финансы бутика.**

Главный вопрос, на который она отвечает: открыл компанию, выбрал бутик — и сразу видно,
сколько стоит закупка, сколько внесено депозитом, сколько заплатил Санжар и сколько осталось оплатить.

## Две версии — одна программа
- **Облако:** https://china-uchet.onrender.com — с любого телефона и компьютера. Входа нет: программа открывается по
  обычной ссылке, без логина, пароля и ключей. Данные в Postgres (Supabase), хостинг Render — оба на бесплатных тарифах.
  Бесплатный Render засыпает после 15 минут тишины, программа сама себя будит раз в 10 минут; если всё же уснул —
  первое открытие займёт ~30 секунд.
- **Локально:** двойной клик по **`Запустить.command`** → http://localhost:8902, данные в файле `china.db`.

Перенос данных между ними: «Настройки → Скачать .db» на одной стороне и «Настройки → Загрузить базу из файла .db» на другой.

## Как пользоваться
1. **Компании.** При первом запуске страница пустая — кнопка «+ Создать компанию», указываете дату создания
   (название — по желанию). В списке у каждой компании: дата, число бутиков, стоимость закупок, оплачено, осталось оплатить.
2. **Бутики.** Внутри компании — «+ Добавить бутик»: город, номер или название, комментарий. Бутик можно открыть,
   изменить или удалить (с подтверждением; удаляются и его товары с платежами).
3. **Закупка бутика.** «+ Добавить товар»: название, количество, цена, стоимость позиции, комментарий.
   Обязательно только название. Если указаны количество и цена, стоимость считается сама; её можно поправить вручную.
4. **Финансы бутика** — блок внизу страницы:
   - **Общая стоимость закупки** — сумма товаров. Если у товаров нет сумм, можно переключить на «указать вручную»
     и ввести одну сумму. Работает только один способ, двойного учёта нет.
   - **Депозит** — залог или предоплата: сумма, дата, комментарий. Может быть нулём. Сразу вычитается из стоимости
     закупки, отдельным платежом его вносить не нужно. Учитывается отдельно от денег Санжара.
   - **Оплаты Санжара** — история платежей с датой, суммой, комментарием: только его собственные деньги.
     Платежей можно добавить несколько, ошибочные — править и удалять.
   - **Получение товара** — «Не получен», «Получен частично» (с количеством по каждому товару), «Получен полностью», дата, комментарий.
     Оплата и получение — разные процессы: оплаченный товар не становится полученным сам.

5. **Поставщики и товары** — вторая вкладка на главной. Общий справочник всех закупленных товаров, к бутикам не привязан:
   поставщики с местом на рынке и телефонами, их накладные (номер, дата, итог, залог) и товары с ценой прихода в юанях.
   Поле поиска находит товар по артикулу (дефисы и пробелы не важны) или по части названия. Один артикул бывает
   у разных поставщиков с разной ценой — показываются все. Строки, прочитанные с накладной неуверенно, помечены «проверить».
   Накладные загружаются файлом `.json` кнопкой «Загрузить накладные»; повторная загрузка того же файла ничего не задваивает.
   Файлы из папки `seed/` программа загружает сама при запуске, каждый ровно один раз (отметка хранится в базе по хэшу
   файла), поэтому удалённое или исправленное в программе после перезапуска не возвращается.
   В `seed/nakladnye-2026-10-14-15.json` — накладные 14–15 октября 2026 (11 поставщиков, 144 товара).
   Владелец сам решил загрузить их через репозиторий, поэтому эти цены и телефоны поставщиков видны на GitHub.

## Как считаются деньги
Для каждого бутика программа отдельно хранит и показывает:

| Показатель | Как считается |
|---|---|
| Стоимость закупки | сумма товаров или введённая вручную сумма (один из двух способов) |
| Депозит | залог / предоплата: внесённая сумма, **вычитается из стоимости сразу** |
| Заплатил Санжар | сумма его платежей (собственные деньги) |
| Оплачено | депозит + платежи Санжара |
| **Осталось оплатить** | **стоимость − депозит − платежи Санжара**, не ниже нуля |
| Переплата | если оплачено больше стоимости — показывается отдельной строкой |

Депозит и платежи Санжара — разные суммы, каждая учитывается один раз. Платежа «из депозита» нет: депозит уже вычтен.
Все цифры пересчитываются после любого добавления, изменения или удаления.

Пример: закупка 220,5 $, депозит 100 $, Санжар заплатил 50 $ → осталось оплатить 70,5 $.

*Записи «из депозита» из версии 7.0 в базе сохранены, но в расчёт не входят (депозит уже вычтен) и помечены в списке платежей — их можно удалить.*

Итоги компании — сумма показателей её бутиков; на экране компаний те же итоги по каждой компании.

## Голосовой ввод из Telegram
Бот **@Kitaibizmartbot** (включается переменными окружения, работать можно и без него). Наговариваете обычными словами —
по-кыргызски, по-русски, вперемешку — бот сам заводит бутики и товары, записывает депозит и платежи, отмечает
получение товара и отвечает цифрами из базы. Под каждым ответом кнопка «↩️ Отменить».
Команды: `/итоги` `/долги` `/бутики` `/отмена` `/помощь`.
Как устроено: голос → Whisper на Groq → модель с вашим справочником компаний и бутиков → те же `/api/…`, что и на сайте.
Управляет только владелец (его id в `KN_TG_ALLOW`), чужим бот отвечает отказом.

## Из чего состоит
- `server.py` — сервер и вся логика: стандартная библиотека Python + SQLite локально, Postgres через pg8000 в облаке
  (переключается переменной `DATABASE_URL`). Таблицы: `companies`, `boutiques`, `boutique_items`, `boutique_payments`,
  `settings`, справочник — `suppliers`, `supplier_invoices`, `catalog_items`.
- `web/index.html`, `web/app.css`, `web/app.js` — одностраничный интерфейс, переходы между экранами без перезагрузки.
- `tgbot.py` — голосовой помощник в Telegram.
- `render.yaml`, `requirements.txt` — облачная сборка.

### Данные прежней версии
Раньше программа вела партии из Китая, поставщиков и инвесторов. Эти таблицы (`partners`, `stores`, `shipments`,
`shipment_items`, `payments`, `investments`, `investor_payouts`) **в базе не трогаются** и попадают в выгрузку `.db`,
но в новом интерфейсе не показываются и в новые расчёты не входят. Файл `.db` прежней версии тоже можно загрузить —
он откроется, новые таблицы добавятся пустыми.

## Где данные
- база — файл `china.db` в этой папке (можно копировать как обычный файл; «Настройки → Скачать .db» скачивает его же);
- резервные копии — папка `backups/`, создаются сами при каждом запуске, хранятся 30 последних.

## Переменные окружения облака
`DATABASE_URL` (строка подключения Supabase, session pooler :5432) · `KN_PG_SCHEMA=china` ·
`KN_KEEPALIVE_URL` (самопробуждение) · `PYTHON_VERSION` · для бота: `KN_TG_TOKEN`,
`KN_TG_SECRET`, `KN_TG_ALLOW`, `KN_TG_HOOK_URL`, `KN_AI_KEY` (ключ Groq), необязательный `KN_TG_THREAD`.

## Доступ
Входа в программу нет: любой, кто знает адрес, видит и может менять все данные, в том числе скачать и заменить базу целиком
(«Настройки → Данные»). Поэтому адрес стоит держать при себе, а базу время от времени скачивать файлом `.db` — это копия
на случай, если что-то изменили или удалили по ошибке. Бот в Telegram по-прежнему отвечает только владельцу (`KN_TG_ALLOW`).
Таблица пользователей прежней версии осталась в облачной базе нетронутой, но больше не используется; переменные
`KN_AUTH`, `KN_OPEN_KEY`, `KN_ADMIN_PASSWORD`, `KN_SECRET` программе не нужны, их можно удалить в настройках Render.
